入口函数 - main.rs

入口函数

src/main.rs:18 — #[tokio::main] async fn main() 是整个程序的入口。

功能流程

  1. 配置初始化：调用 config::init() 确保 config.toml 存在（不存在则写入默认配置）
  2. 命令行参数处理：
    • 第一个参数为 "docs" → 调用 doc_generate() 生成文档 HTML
    • 第一个参数为 "cookie" → 调用 extract_cookies_to_json() 导出浏览器 cookie
  3. 启动 tokio 服务器：绑定 127.0.0.1:{port}（默认 7878），使用 tokio 多线程 runtime； 接受连接后 tokio::spawn 交给 connect::handle_connection 异步处理
  4. 请求处理：handle_connection 异步读取请求头 → spawn_blocking 包装 root_rules（路由在阻塞线程池里同步执行） → 渲染响应 → 异步写回
  5. 并发受控：全局 Semaphore 限制同时处理的最大请求数 = max_concurrent * 2（默认 2 × CPU 核心数）。获取许可后才进入 spawn_blocking，防止阻塞线程池（上限 512）被耗尽

connect 模块 - lib.rs

位置

src/lib.rs 中的 pub mod connect 模块。

核心函数

handle_connection()

签名: pub async fn handle_connection(mut stream: tokio::net::TcpStream)

每个 HTTP 请求的入口处理函数（async）：

  1. 读取请求头：在 growable Vec<u8> 缓冲区读取到 \r\n\r\n 为止，带 30 秒空闲超时、 16 KB 头尺寸上限；旧版固定 [u8; 1024] 缓冲区与 extract_between_spaces 已移除

  2. 解析请求：从请求行提取 method / path / version，并扫描 Connection 头；同时判定是否为文档路由 (/、/docs/*、/index/*、/favicon.ico 是文档路由)。

  3. 并发控制：从全局 Semaphore 获取 1 个许可（上限 max_concurrent * 2）

  4. 调度：tokio::task::spawn_blocking(move || root_rules(path, params))， 路由在阻塞线程池里同步执行，pub fn get(para: HashMap<String,String>) -> Result<String, Error> 的签名不变，路由作者无需学习 async

  5. 渲染：render() 把 ShowToUser 转为 (status, content_type, body)：

    • Ok(...) → 200 OK，Content-Type 按枚举类型决定（HTML / application/xml / 文件 MIME）
    • 错误 downcast_ref::<HttpError>() 命中 → 用 HttpError.status + HttpError.message
    • 未命中（普通 anyhow） → 兜底 500 Internal Server Error

  6. 写回：async write_all，响应头带 Connection: keep-alive / Connection: close。

    作用域：keep-alive 仅对文档/静态路由生效，即 /、/docs/*、/index/*、/favicon.ico。 对动态 RSS 路由（抓取上游），服务器始终返回 Connection: close，每次请求一次连接， 避免长期占着 spawn_blocking 线程池的许可。判定规则见 lib.rs 中的 is_doc_route。

show_index_doc()

签名: pub fn show_index_doc() -> Result<String, Error>

读取二进制同目录下的 index/index.html 文件，返回 HTML 字符串。

show_doc()

签名: pub fn show_doc(path: &str) -> Result<String, Error>

读取二进制同目录下的文档 HTML 文件（如 /docs/new.html → 读取 docs/new.html）。 如果文件不存在，返回 index/404.html 内容。

serve_static()

签名: pub fn serve_static(path: &str) -> ShowToUser

根据文件扩展名决定 MIME 类型：.html/.md 走 show_doc（HTML），其他静态资源（CSS/JS/SVG/PNG/字体等） 走 read_file_bytes 返回 File 变体。找不到时降级为 Html { res: Err(...) }。

mime_type()

签名: pub fn mime_type(path: &str) -> &'static str

根据扩展名返回 MIME 类型：.css → text/css，.js → application/javascript， .svg/.png/.jpg/.gif/.ico → 对应图片类型，.woff2/.woff/.ttf → 字/font 类型， .json/.xml → application/...; charset=utf-8，缺省 text/html; charset=utf-8。

request_rules()

签名: pub fn request_rules(url: &str, parameters: HashMap<String, String>) -> Result<String, anyhow::Error>

二级路由注册表，使用 const 静态数组匹配 URL 路径到具体路由器：

#![allow(unused)]
fn main() {
pub fn request_rules(url: &str, parameters: HashMap<String, String>) -> Result<String, anyhow::Error> {
    const ROUTES: &[(&str, fn(HashMap<String, String>) -> Result<String, anyhow::Error>)] = &[
        ("/nmc_alarm", nmc_alarm::get),
        // ... 其他路由
    ];
    if let Some(handler) = ROUTES.iter().find(|(path, _)| *path == url) {
        if is_route_disabled(url) {
            warn!("Route {} is disabled", url);
            // 返回 HttpError::not_found → 服务器渲染层回响应 404
            return Err(anyhow!(HttpError::not_found("404NotFound")));
        }
        debug!("Route {} matched, fetching", url);
        let result = (handler.1)(parameters);
        // ...
        result
    } else {
        warn!("Unregistered route: {}", url);
        Err(anyhow!(HttpError::not_found("404NotFound")))
    }
}
}

注册的路由会先检查 config.toml 中的 routes.disabled 列表，若被禁用则返回 HttpError::not_found（渲染为 404）。

如何添加新路由

参考 new_router_cn.md，步骤：

  1. 在 src/router/ 下新建 .rs 文件，实现 pub fn get(para: HashMap<String,String>) -> Result<String, Error> （同步签名，内部使用 fetch_reqwest_get 等 easyuser 函数即可；抓取失败直接 ? 向上抛出即可， easyuser 会自动包装为 HttpError 502）
  2. 在 src/router/mod.rs 中添加 pub mod 你的路由名;
  3. 在 request_rules.rs 的 ROUTES 常量数组中添加 ("/你的路由名", 你的路由名::get) 条目
  4. 在 env/docs_md/ 下编写对应的路由文档 .md 文件
  5. 如需自定义 HTTP 状态码，用 anyhow!(HttpError::xxx("原因")) 抛出（参见 easyuser_cn.md 错误类）

文档生成器 - doc.rs

位置

src/doc.rs

概述

将 docs_md/ 目录下的 Markdown 文件批量转换为带样式的 HTML 文档页面。在终端中执行 ./env/rssust docs 触发。

核心函数

doc_generate()

签名: pub fn doc_generate() -> Result<(), Error>

执行流程

  1. 定位目录：以二进制文件所在目录为基础，输入目录为 ./docs_md，输出目录为 ./docs
  2. 生成 SUMMARY.md：自动扫描 docs_md/ 下的所有 .md 文件，按分类生成导航目录
  3. 转换：使用 mdbook 库将 Markdown 转为 HTML
  4. 后处理：将 official/ 子目录下的 HTML 提升到 docs/ 根目录，修复所有资源文件和页面链接的路径

页面功能

  • 侧边栏导航：可折叠/展开，支持关键词搜索过滤目录
  • 文章搜索：实时高亮文章中的匹配文本
  • 代码高亮：支持 Rust、Python、JavaScript、Bash、XML 语言
  • 响应式设计：深色主题，自适应布局

样式特点

  • 深紫色渐变背景
  • 代码块深色底 + 彩色高亮
  • 胶囊形状的“当前页面“指示器
  • 紫蓝色点缀色
